    Correctness of Quicksort #

    We define functional quicksort over a linearly ordered type and prove it correct:

    • quicksort_perm : the output is a permutation of the input (nothing lost or invented);
    • quicksort_sorted : the output is sorted in nondecreasing order;
    • quicksort_correct: the conjunction — the specification of a sorting function.

    Everything is proved internally from the recursive definition, with no sorry and no postulated lemma. The only axioms used are Lean's standard classical foundations.

    source
    def Thesis.Sort.Sorted {α : Type u_1} [LinearOrder α] (l : List α) :
    Prop

    A list is sorted when its elements appear in pairwise nondecreasing order. This is exactly List.Pairwise (· ≤ ·): every earlier element is ≤ every later one.

    Equations
    • Thesis.Sort.Sorted l = List.Pairwise (fun (x1 x2 : α) => x1 ≤ x2) l

      @[irreducible]
      def Thesis.Sort.quicksort {α : Type u_1} [LinearOrder α] :
      List α → List α

      Functional quicksort. The head p of a nonempty list is the pivot; the tail is partitioned into the elements ≤ p and the elements > p (encoded as ¬ (· ≤ p)), each recursively sorted, and the results concatenated around the pivot.

      Termination is by the length of the list: each filter cannot increase the length, and the tail is strictly shorter than p :: rest.

      Equations
      • Thesis.Sort.quicksort [] = []
      • Thesis.Sort.quicksort (p :: rest) = Thesis.Sort.quicksort (List.filter (fun (x : α) => decide (x ≤ p)) rest) ++ p :: Thesis.Sort.quicksort (List.filter (fun (x : α) => !decide (x ≤ p)) rest)
