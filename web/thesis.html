0.What you need to know

The mathematics assumes only an undergraduate logic background. Concretely, the reader should be comfortable with:

  1. Propositional formulas built from atoms with the connectives $\neg$ (not) and $\to$ (implies).
  2. Truth-table semantics: a valuation assigns true/false to atoms, and that determines the truth value of any formula.
  3. Natural deduction: deriving a formula from assumptions using inference rules, including hypothesis discharge (as in $\to$-introduction) and a classical rule (reductio ad absurdum).
  4. Structural induction on the shape of a formula, and induction on a list.

That is the whole prerequisite for the mathematics. To read the code, you need a little about how Lean represents proofs — Section 1.

1.How Lean works (a primer)

Lean 4 is both a programming language and a proof assistant. Five ideas are enough to read everything below.

1.1 Propositions are types; proofs are terms (Curry–Howard)

In Lean a proposition $P$ is a type, and a proof of $P$ is a term (a value) of that type. Writing theorem foo : P := e means "e is a term whose type is P." There is nothing else to "trust": to have a proof is to have such a term, and the kernel checks the term has the claimed type.

1.2 Inductive types are inference systems

An inductive type is declared by its constructors — the only ways to build its values. When the type lives in Prop, its constructors read exactly as inference rules, and a value of the type is a derivation tree. Our calculus is declared this way:

As inference rules
$$\dfrac{\Gamma,\varphi\vdash\psi}{\Gamma\vdash\varphi\to\psi}\;({\to}\mathrm{I}) \qquad \dfrac{\Gamma\vdash\varphi\to\psi\quad\Gamma\vdash\varphi}{\Gamma\vdash\psi}\;({\to}\mathrm{E})$$ A proof of $\Gamma\vdash\psi$ by ${\to}\mathrm{E}$ is a pair of subproofs.
As constructors of an inductive family
inductive ND : Set Formula → Formula → Prop
| impI : ND (insert φ Γ) ψ → ND Γ (φ ⟶ ψ)
| impE : ND Γ (φ ⟶ ψ) → ND Γ φ → ND Γ ψ
-- a term `d : ND Γ ψ` IS a derivation tree

So "by induction on the derivation" is just recursion on this tree (Lean writes it induction d with | impI .. | impE .. | ...): one branch per rule.

1.3 Prop vs Type, and sets as predicates

Type holds data (e.g. Formula is data — a tree of constructors). Prop holds propositions. A set of formulas is just a predicate: Set Formula := Formula → Prop, so φ ∈ Γ is literally "Γ φ holds," and insert φ Γ is the set with $\varphi$ added.

1.4 Tactics build the term for you

A block by ... is a small program whose job is to construct the proof term. intro h assumes a hypothesis, apply r uses rule r and leaves its premises as new goals, exact e supplies a finished term, induction recurses, by_cases h : P splits on whether $P$ holds (classically). Whatever the tactics do, the output is a term the kernel re-checks — the tactics are never themselves trusted.

1.5 The kernel and the axiom audit

After elaboration, Lean's small trusted kernel independently verifies the final term against its type. The command #print axioms t then lists every axiom t transitively uses. If a proof had an unfilled gap (sorry), it would show up as the pseudo-axiom sorryAx; a smuggled-in "oracle" would appear by name. Our results show only the three standard classical axioms (Section 9).

Part I — Completeness of Propositional Natural Deduction

2.The objects in play

A compact recap (full treatment in the overview). Falsity is encoded inside the $\{\neg,\to\}$ language as $\bot := \neg(p_0\to p_0)$, which is false under every valuation.

Mathematics
Semantics: $\llbracket p\rrbracket_v=v(p)$, $\llbracket\neg\varphi\rrbracket_v=\neg\llbracket\varphi\rrbracket_v$, $\llbracket\varphi\to\psi\rrbracket_v=\llbracket\varphi\rrbracket_v\to\llbracket\psi\rrbracket_v$.

Tautology: $\forall v,\ \llbracket\varphi\rrbracket_v$.
Goal: $\mathrm{Taut}(\varphi)\Rightarrow\emptyset\vdash\varphi$.
Lean — Syntax.lean / NaturalDeduction.lean
def eval (v) : Formula → Prop
| .atom s => v s | .neg p => ¬ eval v p
| .impl p q => eval v p → eval v q

def IsTautology (φ) := ∀ v, eval v φ
def Bot := ~(.atom "⊥" ⟶ .atom "⊥")

3.Architecture of the proof

Completeness is built in two movements, then composed:

  1. Kalmár's lemma (Section 5): for a fixed valuation $v$, the signed literals of the atoms of $\varphi$ syntactically decide $\varphi$ — they derive $\varphi$ if $v\models\varphi$, and derive $\neg\varphi$ otherwise. Proved by induction on $\varphi$.
  2. Discharge (Section 7): if $\varphi$ is derivable from the literal context for every $v$, then it is derivable from no assumptions. Proved by induction on the list of atoms, eliminating one atom at a time with a classical case split.

For a tautology, the first gives the hypotheses the second needs, and the composition yields $\emptyset\vdash\varphi$. The only "classical" ingredients are the reductio rule of the calculus and a case split on each atom's truth value — there is no appeal to a completeness theorem from outside.

4.Signed literals and the literal context

Fix a valuation $v$. The signed literal of an atom $p$ records what $v$ says about $p$, as a formula: $p$ itself when $v(p)$ is true, $\neg p$ when false. The literal context $\Gamma_v$ over a list of atoms collects these.

Mathematics
$$\mathrm{lit}_v(p)=\begin{cases}p&v(p)\\ \neg p&\text{otherwise}\end{cases}$$ $$\Gamma_v(\,[\,]\,)=\emptyset,\quad \Gamma_v(p::\mathit{rest})=\{\mathrm{lit}_v(p)\}\cup\Gamma_v(\mathit{rest}).$$ A key fact used repeatedly: if $p$ is among the atoms, then $\mathrm{lit}_v(p)\in\Gamma_v$, so it can be used as a hypothesis.
Lean — Completeness.lean
def lit (v) (p : String) : Formula :=
  if v p then .atom p else ~(.atom p)

def litCtx (v) : List String → Set Formula
| []        => ∅
| p :: rest => insert (lit v p) (litCtx v rest)

theorem lit_mem (h : p ∈ ats) :
    lit v p ∈ litCtx v ats

5.Kalmár's lemma, case by case

Statement. For a valuation $v$ and a list of atoms $\mathit{ats}$ covering $\varphi$ (i.e. $\mathrm{atoms}(\varphi)\subseteq\mathit{ats}$): $$\big(\llbracket\varphi\rrbracket_v\Rightarrow \Gamma_v\vdash\varphi\big)\ \wedge\ \big(\neg\llbracket\varphi\rrbracket_v\Rightarrow \Gamma_v\vdash\neg\varphi\big).$$ The proof is by structural induction on $\varphi$. Note the statement carries both halves at once; that is what makes the induction go through (the negation case feeds the two halves into each other).

Lean — the statement
theorem kalmar (v) (ats) :
    ∀ φ, atoms φ ⊆ ats →
      (eval v φ → ND (litCtx v ats) φ) ∧
      (¬ eval v φ → ND (litCtx v ats) (~φ)) := by
  intro φ; induction φ with
  | atom s => ...
  | neg p ih => ...
  | impl p q ihp ihq => ...

Case $\varphi = p$ (an atom)

Since $p\in\mathit{ats}$, the literal $\mathrm{lit}_v(p)$ is in $\Gamma_v$ and is available as a hypothesis. Two sub-cases by the value of $v(p)$:

  • Positive half. If $\llbracket p\rrbracket_v$, i.e. $v(p)$ is true, then $\mathrm{lit}_v(p)=p$, so the hypothesis rule gives $\Gamma_v\vdash p$.
  • Negative half. If $\neg\llbracket p\rrbracket_v$, then $\mathrm{lit}_v(p)=\neg p$, and the hypothesis rule gives $\Gamma_v\vdash\neg p$.

In Lean this is exactly "rewrite lit using whether v p holds, then exact ND.hyp ‹membership›."

Case $\varphi = \neg p$

Here $\llbracket\neg p\rrbracket_v = \neg\llbracket p\rrbracket_v$, so the two halves swap roles and use the induction hypothesis for $p$.

  • Positive half ($\llbracket\neg p\rrbracket_v$, i.e. $\neg\llbracket p\rrbracket_v$): the negative half of the IH for $p$ already gives $\Gamma_v\vdash\neg p$, which is the goal.
  • Negative half ($\neg\llbracket\neg p\rrbracket_v$, i.e. $\neg\neg\llbracket p\rrbracket_v$): classically $\llbracket p\rrbracket_v$ holds, so the positive half of the IH gives $\Gamma_v\vdash p$; then double-negation introduction (dni, a derived rule) gives $\Gamma_v\vdash\neg\neg p$, which is $\Gamma_v\vdash\neg\varphi$.
-- positive half just reuses ihneg; negative half:
fun h' => dni ((ih ..).1 (not_not.1 h'))   -- ⊢ ~~p

Case $\varphi = p \to q$

From $\mathrm{atoms}(p\to q)=\mathrm{atoms}(p)\,{+}\!{+}\,\mathrm{atoms}(q)\subseteq\mathit{ats}$ we get covering hypotheses for both $p$ and $q$, hence both induction hypotheses.

Positive half: assume $\llbracket p\to q\rrbracket_v$; split on $\llbracket p\rrbracket_v$.

  • If $\llbracket p\rrbracket_v$: then $\llbracket q\rrbracket_v$ (apply the implication). The positive IH for $q$ gives $\Gamma_v\vdash q$; weaken to $\Gamma_v,p$ and apply ${\to}\mathrm{I}$ to conclude $\Gamma_v\vdash p\to q$.
  • If $\neg\llbracket p\rrbracket_v$: the negative IH for $p$ gives $\Gamma_v\vdash\neg p$. Apply ${\to}\mathrm{I}$; we must derive $\Gamma_v,p\vdash q$. By weakening $\Gamma_v,p\vdash\neg p$ and by hypothesis $\Gamma_v,p\vdash p$; then ${\neg}\mathrm{E}$ gives $\bot$ and ${\bot}\mathrm{E}$ gives $q$.

Negative half: assume $\neg\llbracket p\to q\rrbracket_v$. Classically this forces $\llbracket p\rrbracket_v$ (else the implication would be vacuously true) and $\neg\llbracket q\rrbracket_v$ (else it would hold). The positive IH for $p$ gives $\Gamma_v\vdash p$; the negative IH for $q$ gives $\Gamma_v\vdash\neg q$. Apply ${\neg}\mathrm{I}$; we must derive $\Gamma_v,(p\to q)\vdash\bot$: by hypothesis $\Gamma_v,(p\to q)\vdash p\to q$, by weakening $\Gamma_v,(p\to q)\vdash p$, so ${\to}\mathrm{E}$ gives $q$; by weakening $\Gamma_v,(p\to q)\vdash\neg q$, and ${\neg}\mathrm{E}$ gives $\bot$.

Why it is a program. The induction here is on the syntax of $\varphi$ (Lean's Formula.rec), not on a derivation. A single run of that recursion turns the truth value of $\varphi$ under $v$ into an actual derivation tree built from the constructors ${\to}\mathrm{I}$, ${\neg}\mathrm{I}$, ${\bot}\mathrm{E}$, ${\neg}\mathrm{E}$ and the derived rule dni. "Completeness as a program," made literal.

6.The context depends only on truth values

The discharge step will perturb the valuation at a single atom. We must know this does not disturb the part of the context built from the other atoms. That is a small congruence lemma: valuations agreeing on a list of atoms produce the same literal context.

Mathematics
If $w_1(x)\leftrightarrow w_2(x)$ then $\mathrm{lit}_{w_1}(x)=\mathrm{lit}_{w_2}(x)$.

Hence if $w_1,w_2$ agree on every atom of $\mathit{ats}$, $$\Gamma_{w_1}(\mathit{ats})=\Gamma_{w_2}(\mathit{ats}).$$ (Induction on $\mathit{ats}$: head by the first fact, tail by the IH.)
Lean — Completeness.lean
theorem lit_congr (h : w1 x ↔ w2 x) :
    lit w1 x = lit w2 x

theorem litCtx_congr (ats) :
    (∀ x ∈ ats, (w1 x ↔ w2 x)) →
    litCtx w1 ats = litCtx w2 ats

7.Discharging the atoms

Statement. For a duplicate-free list $\mathit{ats}$, if $\Gamma_v(\mathit{ats})\vdash\varphi$ for every valuation $v$, then $\emptyset\vdash\varphi$. The proof is by induction on $\mathit{ats}$, removing one atom per step.

Base case $\mathit{ats}=[\,]$

$\Gamma_v(\,[\,]\,)=\emptyset$ for any $v$, so the hypothesis at (say) the all-true valuation already gives $\emptyset\vdash\varphi$.

Step case $\mathit{ats}=p::\mathit{rest}$

We invoke the induction hypothesis on $\mathit{rest}$, so it suffices to show $\Gamma_v(\mathit{rest})\vdash\varphi$ for an arbitrary $v$. Build two perturbed valuations, $v_{\mathsf{T}}$ and $v_{\mathsf{F}}$, that agree with $v$ everywhere except they pin $p$ to true / false respectively. Because $\mathit{rest}$ is duplicate-free and does not contain $p$, the congruence lemma gives $\Gamma_{v_{\mathsf T}}(\mathit{rest})=\Gamma_{v_{\mathsf F}}(\mathit{rest})=\Gamma_v(\mathit{rest})$. Now:

  • The hypothesis at $v_{\mathsf T}$ gives $\;\Gamma_v(\mathit{rest}),\,p\ \vdash\ \varphi$ (since $\mathrm{lit}_{v_{\mathsf T}}(p)=p$).
  • The hypothesis at $v_{\mathsf F}$ gives $\;\Gamma_v(\mathit{rest}),\,\neg p\ \vdash\ \varphi$ (since $\mathrm{lit}_{v_{\mathsf F}}(p)=\neg p$).

These are exactly the two premises of the derived rule of proof by cases (byCases), which is itself built from the classical reductio rule. Combining them discharges $p$ and yields $\Gamma_v(\mathit{rest})\vdash\varphi$, closing the step.

The derived rule used
$$\dfrac{\Gamma,\varphi\vdash\chi \qquad \Gamma,\neg\varphi\vdash\chi}{\Gamma\vdash\chi}\;(\text{by cases})$$ Derivable from classical, negI, negE and weakening.
Lean — Completeness.lean
theorem discharge (ats : List String)
    (hnd : ats.Nodup)
    (H : ∀ v, ND (litCtx v ats) φ) : ND ∅ φ

8.Assembling completeness

Take $\mathit{ats}$ to be the atoms of $\varphi$ with duplicates removed — repetition-free and still covering $\varphi$. Fix any $v$. Since $\varphi$ is a tautology, $\llbracket\varphi\rrbracket_v$ holds, so the positive half of Kalmár's lemma gives $\Gamma_v(\mathit{ats})\vdash\varphi$. As $v$ was arbitrary, the hypothesis of discharge is met, and we conclude $\emptyset\vdash\varphi$.

Mathematics
Completeness. $\mathrm{Taut}(\varphi)\Rightarrow\emptyset\vdash\varphi$.

With soundness, adequacy: $$\mathrm{Taut}(\varphi)\ \Longleftrightarrow\ \emptyset\vdash\varphi.$$
Lean — Completeness.lean
theorem completeness_ND (φ) (h : IsTautology φ) :
    ND ∅ φ :=
  discharge (atoms φ).dedup (List.nodup_dedup _)
    (fun v =>
      (kalmar v (atoms φ).dedup φ
        (fun a ha => List.mem_dedup.2 ha)).1 (h v))

theorem soundComplete (φ) :
    IsTautology φ ↔ ND ∅ φ :=
  ⟨completeness_ND φ, isTautology_of_provable⟩

Reading the Lean: discharge is applied to the dedup'd atom list (with its no-duplicates proof) and to a function that, for each v, hands back the Kalmár derivation — .1 selects the positive half, applied to h v (the tautology at $v$). The whole expression is a single term inhabiting ND ∅ φ.

9.What "verified" guarantees

Because a derivation is a term and the kernel checks it, there is no separate "is the proof correct?" question. The remaining question is what the term assumes, answered by the axiom audit:

Generated certificate
completeness_ND and soundComplete depend only on propext, Classical.choice, Quot.sound — the standard classical foundation shared by all of Mathlib. No sorryAx (no admitted gaps) and no postulated completeness rule appear. The hand-built example derivations depend on no axioms at all, being finite proof terms.

This is the precise sense in which the theorem is "machine-checked": every inference rule is a constructor, every proof is a term the kernel re-verified, and the only assumptions are the three named axioms — nothing specific to this development.

Part II — Correctness of Quicksort

A second, independent development in the same repository: the classical functional quicksort is correct — on any input over a linearly ordered type it returns a list that is both a permutation of the input and sorted. The Lean primer of Section 1 applies unchanged; here the inductive object is the list, and the recursion is on its length.

10.The problem and its specification

A sorting function must do two things: not lose or invent elements (a permutation), and put them in order (sorted). "Sorted" is the pairwise relation: every earlier element is $\le$ every later one.

Mathematics
Sorted: $\;\mathrm{Sorted}(\ell) :\equiv \ell\ \text{is pairwise}\ (\le)$ — for all $i
Permutation: $\;\mathrm{qsort}(\ell) \sim \ell$ (same elements with multiplicity).

Specification: $\;\mathrm{qsort}(\ell)\sim\ell \ \wedge\ \mathrm{Sorted}(\mathrm{qsort}(\ell)).$
Lean — Quicksort.lean
def Sorted (l : List α) : Prop :=
  l.Pairwise (· ≤ ·)

11.The algorithm and termination

Quicksort takes the head of a nonempty list as the pivot $p$, splits the tail into the elements $\le p$ and the elements $> p$, sorts each recursively, and concatenates them around $p$. Because the partitions are computed (by filtering), not structural sub-terms, Lean needs a termination proof: the measure is the list's length, and filtering never increases length, so each recursive call is strictly shorter.

Mathematics
$$\mathrm{qsort}([\,])=[\,]$$ $$\mathrm{qsort}(p::r)=\mathrm{qsort}(r_{\le p})\ {+}\!{+}\ p::\mathrm{qsort}(r_{>p})$$ where $r_{\le p}=\mathrm{filter}(\cdot\le p)(r)$ and $r_{>p}$ its complement.

Termination. $|\mathrm{filter}(q)(r)|\le|r|<|p::r|$, so both recursive arguments are strictly shorter; well-founded recursion on length is justified.
Lean — Quicksort.lean
def quicksort : List α → List α
  | [] => []
  | p :: rest =>
      quicksort (rest.filter (fun x => decide (x ≤ p)))
        ++ p :: quicksort (rest.filter (fun x => ! decide (x ≤ p)))
  termination_by l => l.length
  decreasing_by
    all_goals simp_wf
    all_goals exact le_trans (length_filter_le _ _)
                            (le_of_eq (by simp))

12.It returns a permutation

By induction on the length. The two recursive calls permute the two halves (induction hypotheses); gluing them around the pivot permutes $\mathrm{qsort}(r_{\le p}) {+}\!{+}\, p::\mathrm{qsort}(r_{>p})$ into $r_{\le p} {+}\!{+}\, p :: r_{>p}$; moving the pivot to the front and recombining the two filtered halves recovers $p::r$.

Mathematics
Permutation. $\;\forall \ell,\ \mathrm{qsort}(\ell)\sim\ell.$

Steps: IH on each half $\Rightarrow$ congruence of $\sim$ over ${+}\!{+}$ and $::$ $\Rightarrow$ pivot-to-front ($\mathrm{perm\_middle}$) $\Rightarrow$ recombine filters ($r_{\le p}{+}\!{+}\,r_{>p}\sim r$).

Corollary. membership is preserved: $a\in\mathrm{qsort}(\ell)\iff a\in\ell$.
Lean — Quicksort.lean
theorem quicksort_perm :
    ∀ l : List α, quicksort l ~ l
  | [] => by simp
  | p :: rest => by
      rw [quicksort_cons]
      have ih1 := quicksort_perm (rest.filter _)
      have ih2 := quicksort_perm (rest.filter _)
      refine (ih1.append (ih2.cons p)).trans ?_
      refine (perm_middle).trans ?_
      exact (filter_append_perm _ rest).cons p

13.It returns a sorted list

Again by induction. The two recursive results are sorted (IHs). Every element of the small half is $\le p$ and every element of the large half is $\ge p$ — read off the filter tests, transported back through the permutation. A concatenation $A {+}\!{+}\, (p::B)$ is sorted when $A$ is sorted, $p::B$ is sorted, and every element of $A$ is $\le$ every element of $p::B$ — which the pivot bounds supply.

Mathematics
Sortedness. $\;\forall \ell,\ \mathrm{Sorted}(\mathrm{qsort}(\ell)).$

Pivot bounds: $a\in\mathrm{qsort}(r_{\le p})\Rightarrow a\le p$; $\ b\in\mathrm{qsort}(r_{>p})\Rightarrow p\le b$.

Then $\mathrm{Sorted}(A{+}\!{+}\,p::B)$ from: $\mathrm{Sorted}(A)$, $\mathrm{Sorted}(p::B)$, and the cross-bound (every $a\in A$ is $\le$ everything in $p::B$, by transitivity through $p$).
Lean — Quicksort.lean
theorem quicksort_sorted :
    ∀ l : List α, Sorted (quicksort l)
  | [] => by simp [Sorted]
  | p :: rest => by
      -- IHs: both halves sorted
      -- hsmall: every elt of the ≤-half is ≤ p
      -- hlarge: every elt of the >-half is ≥ p
      rw [quicksort_cons, pairwise_append]
      refine ⟨ih1, ?_, ?_⟩
      · rw [pairwise_cons]; exact ⟨hlarge, ih2⟩
      · intro a ha b hb
        rcases List.mem_cons.1 hb with h | h
        · subst h; exact hsmall a ha
        · exact le_trans (hsmall a ha) (hlarge b h)

14.Correctness and the axiom audit

The two halves combine into the specification, and the same audit confirms the proof rests only on the standard classical axioms.

Mathematics
Correctness. $$\forall\ell,\ \ \mathrm{qsort}(\ell)\sim\ell\ \wedge\ \mathrm{Sorted}(\mathrm{qsort}(\ell)).$$ Quicksort returns a sorted permutation of its input — the full specification of a sorting algorithm.
Lean — generated certificate
theorem quicksort_correct (l : List α) :
    quicksort l ~ l ∧ Sorted (quicksort l) :=
  ⟨quicksort_perm l, quicksort_sorted l⟩

-- audit.txt:
-- quicksort_correct depends on axioms:
--   [propext, Classical.choice, Quot.sound]

No sorryAx, no postulated sorting lemma — quicksort's correctness carries the identical three-axiom footprint as the completeness theorem of Part I.

15.Cross-validation by an automated prover

As with Part I, we gave the automated prover Harmonic Aristotle the algorithm cold — the definition of quicksort and its unfolding equation, with the correctness proof and both lemmas withheld — and asked it to prove quicksort_correct. It works inside Lean, so its output is kernel-checked to the same standard.

It rediscovered the same decomposition (a permutation lemma and a sortedness lemma, conjoined). The sortedness proof tracks ours. For permutation, though, it found a different route: where the hand proof rearranges the partitions structurally, Aristotle reduced "is a permutation" to equality of element counts and discharged it by automation —

Two routes to the same lemma
Hand proof: structural — glue the sorted halves around the pivot, move the pivot to the front, recombine the filtered partitions ($\mathrm{perm\_middle}$, $\mathrm{filter\_append}$).

Aristotle: $\;a\sim b \iff \forall x,\ \mathrm{count}(x,a)=\mathrm{count}(x,b)$, then close the arithmetic of counts automatically.

Same theorem, same three axioms (propext, Classical.choice, Quot.sound), no sorry.
Lean — aristotle/QuicksortFull.lean
theorem quicksort_perm (l : List α) :
    quicksort l ~ l := by
  induction' n : l.length
    using Nat.strong_induction_on with n ih generalizing l
  rcases l with _ | ⟨p, l⟩ <;>
    simp_all +decide [List.perm_iff_count]
  · unfold quicksort; aesop
  · intro a; rw [quicksort_cons]
    simp +decide [List.count_append, List.count_cons]
    grind +suggestions

The takeaway mirrors Part I: the correctness of quicksort is not an artifact of one author's proof — an independent agent, given only the algorithm, arrives at the same verified theorem, and is even free to find its own argument for the harder lemma. Its proof is checked by the same kernel and rests on the same three axioms.
