What a green run proves

The public CI workflow starts from a fresh GitHub runner, performs three complementary verification checks, and then publishes the actual Lean output.

1

Lean builds the two developments

lake build elaborates the source and asks Lean's kernel to type-check every proof term imported by the library root. This covers propositional syntax and semantics, the natural-deduction calculus, soundness, Kalmár completeness, and the quicksort development. CI also builds the independent Foundation bridge as its separate Lake target.

2

The axiom certificates are regenerated

Lean runs #print axioms for the principal results in both developments. CI compares the generated text with the certificates committed in the repository and fails if their transitive dependency lists change.

3

The independent reconstructions compile

Three standalone Aristotle case-study files are checked separately. They are not silently inherited through the main library build: CI invokes Lean on each file explicitly.

4

The actual Lean output is published

Lean prints the exact types of the principal theorems, evaluates concrete quicksort inputs, and reports the transitive axioms of each audited result. CI compares that transcript with the public copy, embeds it in the run certificate, and uploads it as a commit-labelled artifact.

Natural deduction

correccion: derivability preserves semantic truth.

completitud_ND: every tautology is derivable from the empty context.

correccion_completitud: tautology and empty-context derivability are equivalent.

Quicksort

quicksort_permutacion: the result is a permutation of the input.

quicksort_ordenada: the result is sorted.

quicksort_correcto: both properties hold together.

The axiom audit, in plain language

The certificate reports every axiom on which each named theorem transitively depends. The current committed output for all principal results contains only Lean/Mathlib's standard foundational constants:

Audited resultsReported dependencies
completitud_ND, correccion_completitud, correccion propext, Classical.choice, Quot.sound
quicksort_correcto, quicksort_permutacion, quicksort_ordenada propext, Quot.sound
ej_identidad, ej_eliminacion_doble_negacionNo axioms
No admitted gap in the audited results. Lean represents a proof completed with sorry using sorryAx. If an audited theorem depended on one, it would appear in the regenerated list and the committed-certificate comparison would fail. A custom postulated “oracle” used by one of those results would likewise appear by name. Neither occurs in the current certificates.

This statement is deliberately scoped: the audit certifies the named results and everything they use transitively. It is not a textual claim that no unused declaration anywhere in every dependency could contain an axiom.

Reproduce the checks locally

The repository pins the Lean release in lean-toolchain, locks package revisions in lake-manifest.json, and pins the Foundation dependency in lakefile.lean. Install elan, clone the repository, then run:

lake exe cache get   # download the matching prebuilt Mathlib cache
lake build           # kernel-check the main library
make check           # build, audit both developments, check Aristotle files

make check is the one-command reproduction of the substantive CI gate. The source of that gate is public in ci.yml; the generated certificates are natural-deduction/audit.txt and quicksort/audit.txt.

Codespaces is optional exploration

Codespaces is useful when you want a browser-based editor, hover information, and an interactive Lean session without installing Lean locally. It is not needed to trust the public result: the CI logs already show the clean-run verification, and local make check is the independent reproduction path.

First launch can be large. The development imports Mathlib. A new environment must download and unpack its pinned dependency cache, which can occupy several gigabytes and may make the Codespace look idle while setup finishes. A repository prebuild can shift most of this work ahead of the visitor's first session; without one, allow time and storage for initial setup.

Inspect the evidence

  • Plain-text Lean transcript — exact theorem types, evaluations, and axiom output generated in CI.
  • Natural-deduction proof source — calculus, soundness, bridge, and completeness.
  • Quicksort proof source — algorithm, permutation, sortedness, and combined correctness.
  • Foundation cross-validation — the independently compiled semantic bridge.
  • Generated API documentation — browse declarations and exact theorem types.
  • Aristotle reconstructions — the three separately compiled case-study files.
  • Release artifacts — the thesis reports and AI-reconstructed proofs reference.

The trust boundary

Formal verification does not mean “trust nothing.” The result relies on Lean's kernel, the pinned compiler and libraries, and the ordinary computing platform running them. Within that boundary, tactics and AI-generated suggestions are not trusted: they must produce proof terms that the kernel accepts. The audit then makes the explicit logical assumptions of the main theorems visible.
